## YukiHook 关键事实（已核对源码与 Maven）

- 文档站是 1.6.4，**Maven 只有 1.5.0**（1.6.4 的 pom 在 Central 与作者公共仓库均 404）；1.5.0 已含 parasitic 包与 `registerModuleActivities(BuildContext, String)`、`ModuleActivity`、`injectModuleResources`、`applyModuleTheme`、`withApplicationReady`、`@YukiHookLibXposedEntry`。
- 机制：hook `IActivityManager$Stub$Proxy.startActivity`（Q+ 加 IActivityTaskManager）改写 Intent → `performLaunchActivity` 还原 → `newActivity` 失败后用模块 ClassLoader 实例化 → `callActivityOnCreate` 注入资源。
- 硬依赖：androidx.appcompat 1.7.1、kavaref、betterandroid、hiddenapibypass 6.2、kotlin-stdlib 2.4.21。
- 约束：proxy 必须宿主已声明且 launchMode=standard；资源包 ID 不能用 0x7f；手写 META-INF/xposed 会导致编译失败；模块 Activity 存活时热重载会被拒。
- 待真机验证：KSP 能否配 AGP 9.3.2 / Kotlin 2.4.10；两个宿主 proxy 实测 launchMode；资源注入在 API 36/37 的表现。

## 豆包设置页打不开的真因与修复（master 已合并，1.4.0）

**现象**：FAB 可拖动、点击有日志，`startActivity` 不抛异常，但模块页永远不出现。

**排查路径（真机 diag.log + dumpsys，不要凭猜）**：
1. `[REG] ok` 在豆包 5 个进程（含 `:Setting`）全部成功 → 不是「非首进程没注册」；
2. 点击有 `[FAB] launch/startActivity ok`，但**没有任何 `[UI] onCreate`** → 不是崩溃在 onCreate；
3. `dumpsys activity activities` 看到 `ActivityRecord{.../.activity.SettingsActivityNext}` 早就存在，
   `Intent {... (has extras)}`（说明 YukiHook 的 wrap 生效）、`reportedDrawn=false`、`mAppStopped=true`。

**根因**：proxy 已被上一次失败的启动"污染"，记录一直留在栈里且从未画出。之后每次 start 都命中同一条
ActivityRecord，按 singleTop 语义只回调 onNewIntent，**根本不会再实例化** → 代理替换逻辑没有执行机会；
而 startActivity 本身不报错，于是表现成"点了没反应"。`SettingsActivityNext` 还额外带 signature 权限。

**修复**：`HostCatalog` 拆出与 FAB 白名单解耦的 `PROXY_ACTIVITY` 候选表，豆包首选
`com.bytedance.android.doubaoime.activity.LauncherActivity`（导出、无权限、当前不在栈里）。
选 proxy 的规则写进 HOST_NOTES：**导出 + 无权限限制 + 当前不在 Activity 栈里**。

**YukiHook 1.5.0 实测事实**：
- 热重载后 `onHook` 会重跑（diag 里能看到 `loadApp → PROBE installed → REG → reloaded`），旧 Hook 不会残留；
- `module.prop` 由 KSP 生成，只有 `minApiVersion=101 / targetApiVersion=102 / staticScope / autoHotReload`，
  名称与描述取自 APK 的 `android:label` / `android:description`；
- `ModuleActivity.delegate` 走 `ModuleClassLoader`，是**模块优先**（先模块 APK 再宿主），所以 Compose 版本冲突风险低；
- `appContext` 已废弃，用 `hostApplication`。

**收尾**：删除临时 `LaunchProbe`、1.2s 自检、逐段 UI 日志；保留注册/启动失败、设置页 onCreate、崩溃留证。
